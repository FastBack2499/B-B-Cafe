# کافه نان و کره

منوی عمومی و صندوق کافه با رابط فارسی راست‌به‌چپ. مرورگر می‌تواند منوی عمومی و پنل کارکنان را به‌صورت دو برنامهٔ مستقل نصب کند. سفارش‌ها و اطلاعات مالی در PostgreSQL ذخیره می‌شوند و ثبت و تسویه به اتصال سرور نیاز دارد.

## اجرای محلی

نیازمندی‌ها شامل Node.js 22 یا جدیدتر، Python 3.12 و PostgreSQL است. اگر پایگاه و حساب‌های این workspace از قبل آماده‌اند، `./scripts/dev` را اجرا کنید. آدرس پنل خصوصی در ترمینال نمایش داده می‌شود. اطلاعات حساب‌های محلی آماده‌شده در `.local/accounts` است.

برای نصب در محیط تازه، ابتدا یک پایگاه PostgreSQL بسازید و `.env.example` را به `.env` کپی کنید. `DATABASE_URL` را وارد کنید و برای کلید Django و مسیر ورود دو مقدار مستقل تصادفی بسازید. فایل `.env` را خصوصی نگه دارید.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm --prefix frontend ci

set -a
source .env
set +a
.venv/bin/python backend/manage.py migrate
.venv/bin/python backend/manage.py import_cafe \
  --menu '/path/to/Menu cafe_fixed.xlsm' \
  --accounting '/path/to/Cafe_Accounting_1405_fair_withdrawals.xlsx'
.venv/bin/python backend/manage.py createsuperuser
.venv/bin/python backend/manage.py create_barista barista
./scripts/dev
```

فرمان ورود داده را برای انتقال اولیه با `--dry-run` اجرا کنید تا بدون ثبت دائمی بررسی شود. اجرای دوباره فقط رکوردهای منبعِ موجودنشده را اضافه می‌کند و ویرایش‌های قبلی را بازنویسی نمی‌کند. فایل‌های اکسل ورودی اجرای محلی فرمان هستند.

منوی عمومی روی `http://localhost:3000/` است. ورود هر دو حساب از طریق `http://localhost:3000/<STAFF_ROUTE_KEY>` انجام می‌شود. برای بررسی نصب PWA روی همان رایانه، به‌جای سرور Next توسعه، برنامه را با `DJANGO_API_ORIGIN=http://127.0.0.1:8000 npm --prefix frontend run build` بسازید و با `npm --prefix frontend run start` اجرا کنید. در Vercel از HTTPS استفاده می‌شود.

## گردش کار و داده‌های اکسل

- باریستا سفارش را می‌سازد، سفارش‌های خودش را می‌بیند و می‌تواند آن‌ها را تسویه یا لغو کند. مدیر تمام سفارش‌ها، مدیریت منو، گزارش فروش و حسابداری را در اختیار دارد.
- قیمت در زمان صدور فاکتور و هزینهٔ متریال در زمان تسویه ثبت می‌شود. گزارش فروش بر پایهٔ روز تسویهٔ تهران است. دادهٔ تاریخی زمان بستن جداگانه ندارد و از زمان ثبت‌شده در Sheet2 استفاده می‌کند. لغو در تاریخچه می‌ماند. کسر تخفیف در گزارش فروش خالص و سود کل اعمال می‌شود.
- محصولات و قیمت‌ها از فایل XLSM می‌آیند. چیدمان دسته‌بندی از ساختار منوی ایوان الهام گرفته است. دسته‌های خالی برای مدیریت باقی می‌مانند و محصول بدون قیمت قابل سفارش نیست. قیمت‌ها و مبالغ سفارش به تومان نمایش داده می‌شوند. هر واحد فایل برابر ۱٬۰۰۰ تومان است و مقدار پایه در پایگاه داده نگهداری می‌شود. از مدیریت منو می‌توان عنوان و ضریب نمایش را تنظیم کرد.
- مقدارهای ثبت‌شده در شیت «دستی» با واحد خود شیت نگهداری می‌شوند و در فروش POS یا صندوق دوباره شمرده نمی‌شوند. هدف اکسل با همان بازه قابل انتخاب است. محاسبهٔ سود در بازهٔ دارای متریال ناقص تا تکمیل مقادیر ناقص می‌ماند.
- حساب صندوق طبق دفتر اکسل و به تومان است. واریز کامیار به صندوق، طلب کافه از او را کاهش می‌دهد. حقوق از صندوق کم می‌شود و بر خالص شرکا اثر ندارد. روزهای خالی تراکنش‌ها در همان ماه باقی می‌مانند. گزارش برداشت و خلاصهٔ سالانه از همان تراکنش‌ها محاسبه می‌شوند.

## انتشار روی Vercel

پیکربندی ریشه از Vercel Services برای اجرای Next.js و Django زیر یک دامنه استفاده می‌کند. Vercel مسیرهای `/api/*` را به Django می‌فرستد. [Vercel Services](https://vercel.com/docs/services) · [Django on Vercel](https://vercel.com/docs/frameworks/full-stack/django)

1. پروژهٔ Vercel را به ریشهٔ مخزن متصل کنید و در تنظیمات Build and Deployment، گزینهٔ Framework Preset را روی Services قرار دهید. PostgreSQL مدیریت‌شده با TLS و نسخهٔ پشتیبان تهیه کنید. برای اتصال سرورلس از آدرس pool‌شدهٔ ارائه‌دهنده استفاده کنید و پارامترهای TLS آن را حفظ کنید.
2. در محیط Production به هر دو سرویس مقدار مشترک و خصوصی `STAFF_ROUTE_KEY` بدهید. در سرویس Django، `DJANGO_SECRET_KEY` تصادفی، `DATABASE_URL`، `DJANGO_ALLOWED_HOSTS` و `DJANGO_CSRF_TRUSTED_ORIGINS` را تنظیم کنید. نمونه: `DJANGO_ALLOWED_HOSTS=cafe.example.com` و `DJANGO_CSRF_TRUSTED_ORIGINS=https://cafe.example.com`. کلید مسیر باید ۲۴ نویسه یا بیشتر و از حروف، اعداد، خط تیره و زیرخط باشد. کلید Django باید دست‌کم ۵۰ نویسه داشته باشد. `DJANGO_DEBUG` را در تولید خاموش بگذارید.
3. از یک ترمینال خصوصی متصل به پایگاه تولید، مهاجرت، ورود فایل‌ها و ساخت دو حساب را مانند بالا انجام دهید. از اعتبارنامه‌های مستقل برای پایگاه آزمایشی و تولید استفاده کنید.
4. پروژه را منتشر کنید و ورود هر دو کاربر، افزودن آیتم، ثبت و تسویه را در دامنهٔ نهایی بررسی کنید. مسیر خصوصی فقط از طریق نشانی به اشتراک گذاشته می‌شود و نشست و نقش Django دسترسی را بررسی می‌کنند.
